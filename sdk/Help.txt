## Edytor
Klawiatura dotykowa pisze w miejscu kursora. Enter robi nową linię z tym samym wcięciem.
D-pad: kursor. L + Lewo/Prawo: początek/koniec linii. L + Góra/Dół: strona w górę/w dół.
B: usuń znak. Y: cofnij. R: wstaw pierwszą podpowiedź. X: Help.
SELECT: pliki projektu. START: wyjście do menu.
Przycisk Uruchom zapisuje pliki i uruchamia program. Błąd pokazuje plik i linię, kursor tam przeskakuje.
Przycisk Graf otwiera edytor grafu (w pliku z grafem) albo robi nowy plik z grafem (patrz Graf 1).

## Program
Program to klasa z metodami static:
static void Main() - raz na starcie.
static void Update() - co klatkę (60 razy na sekundę), logika gry.
static void Draw() - co klatkę po Update, rysowanie.
Jeśli jest Update, program działa jako gra; START wraca do menu.

## Projekt
Projekt to folder: wszystkie pliki .cs w nim kompilują się razem i klasy widzą się nawzajem.
Obrazki i dźwięki są szukane w folderze projektu.
Każda klasa może mieć własne static void Main(), Update() i Draw(), tak jak skrypty na scenie w Unity: program woła je wszystkie, w kolejności klas w projekcie (pliki po nazwie, klasy od góry). Tak działają też pliki z grafem.
Dobrze jest pisać na początku każdego pliku: namespace NazwaProjektu;

## Graf 1: edytor
Graf to program z węzłów zamiast z tekstu (jak Bolt w Unity). Plik z grafem to zwykły plik .cs: jego kod powstaje z grafu, a sam graf jest w ostatniej linii (// @graph ...). W edytorze kodu taki plik jest tylko do czytania: zmieniasz go w Graf.
Nowy graf: w projekcie (folderze) przycisk Graf na zwykłym pliku pyta o nazwę klasy i robi plik z węzłami Update i Draw.
Przepływ (trójkąty) idzie od lewej do prawej i ustala kolejność. Wartości (kółka) to dane, np. wynik Input.Held albo liczba. Pełny znaczek = podłączony.
Połącz: przeciągnij z portu do portu albo dotknij jednego portu, potem drugiego. Wyjście (po prawej) łączy się z wejściem (po lewej), przepływ z przepływem, wartość z wartością.
Usuń połączenie: dotknij przewodu, potem Usuń (albo X). Albo przeciągnij przewód z podłączonego wejścia w puste miejsce. Cofnij wraca o krok.
Węzeł: przesuwasz za nagłówek; dotknij wartości w węźle, żeby ją wpisać (tekst dostanie cudzysłów sam). + Węzeł (albo A): paleta z wyszukiwaniem, np. circle, held, jeśli, dodaj.
L/R: przybliż / oddal. Y: cały graf na ekranie. Gałka albo przeciągnięcie tła: przesuń widok.
Więcej: zmienne grafu, nazwa klasy, klasa z obiektami, następna uwaga, zapisz.
Uwagi: pomarańczowa ramka i lista na górnym ekranie to podpowiedzi generatora, np. węzeł niepodłączony do żadnego zdarzenia.
Każda zmiana od razu zapisuje kod pliku, więc Kod, potem Uruchom działa od razu.
Rysuj tylko w Draw: Draw zaczyna się zwykle od Gfx.Clear, więc to, co narysujesz w Update, zniknie, zanim je zobaczysz.

## Graf 2: własne węzły z kodu
Każda metoda static w pliku z kodem projektu sama staje się węzłem w palecie (kategoria Kod: NazwaKlasy). Nic nie trzeba rejestrować.
class Lib {
    // Odległość dwóch punktów.            <- komentarz nad metodą = opis węzła
    // @node Odległość                     <- (można pominąć) inny tytuł węzła
    static float Dystans(float ax, float ay, float bx, float by) {
        float dx = ax - bx, dy = ay - by;
        return Mathf.Sqrt(dx * dx + dy * dy);
    }
    // @node hide                          <- metoda pomocnicza: bez węzła
    static int Pomocnicza(int a) { return a * 2; }
}
Parametry to wejścia węzła (bez połączenia mają wartość domyślną z typu, np. 0, albo wpisaną), wynik to wyjście result, a przepływ wchodzi i wychodzi jak przy każdym wywołaniu.
Pominięte: Main, Update, Draw (to zdarzenia) i metody bez static. Plik z błędem nie daje węzłów, dopóki go nie poprawisz.
Paleta czyta kod przy wejściu w Graf: po dopisaniu metody wyjdź z grafu (Kod) i wejdź jeszcze raz.
Dwie metody o tej samej nazwie dają jeden węzeł (z pierwszej). Taki węzeł nie pamięta nic między klatkami: to zwykłe wywołanie metody.
Jeszcze nie ma: węzłów z pamięcią (klasa z wejściami i wyjściami) i węzłów złożonych z grafu (podgrafów).

## Graf 3: graf i kod razem
Graf to klasa (nazwa w Więcej > Nazwa klasy), a jego zmienne to pola static tej klasy:
Ball.x = 100;            // z kodu: zmienna x grafu Ball
Węzeł Metoda (wołana z kodu), np. o nazwie Skok, daje metodę grafu: w kodzie Ball.Skok();
W grafie pole innej klasy odczytasz węzłem Wartość z wpisanym wyrażeniem, np. Game.wynik.
Ustaw zmienną zmienia tylko zmienne własnego grafu. Pole innej klasy zmienisz przez metodę w kodzie, która od razu jest węzłem:
static void DodajPunkty(int n) { Game.wynik += n; }
Klasa z obiektami (Więcej): graf staje się klasą bez static, z której robisz obiekty, każdy z własnymi zmiennymi:
var b = new Ball(); b.Skok();
Update i Draw może mieć każdy plik, także graf: program woła je wszystkie, pliki po nazwie. Gfx.Clear zrób tylko w jednym Draw (w pliku, który idzie pierwszy), bo późniejszy Clear zmaże to, co narysowały wcześniejsze pliki.

## Kurs 1: pierwszy program
Ten kurs prowadzi od zera do małej gry. Cała gra jest w przykładzie kurs.cs (uruchom ją z menu, a potem otwórz w edytorze).
Program to tekst, który komputer wykonuje linia po linii. Zmienna to pudełko z nazwą, w którym trzymasz wartość.
class Game {
    static void Main() {                  // tu program się zaczyna
        string imie = "Rycerz";           // string: tekst
        int hp = 100;                     // int: liczba całkowita
        int obrazenia = 15;
        float szybkosc = 2.5f;            // float: liczba z ułamkiem (z f na końcu)
        bool zyje = true;                 // bool: prawda albo fałsz
        hp = hp - obrazenia;              // hp teraz 85
        hp -= obrazenia;                  // to samo krócej: hp teraz 70
        Console.WriteLine(imie + " ma " + hp + " hp");    // wypisze: Rycerz ma 70 hp
        if (hp <= 0) zyje = false;        // if: zrób coś tylko, gdy warunek jest prawdziwy
    }
}
Każda instrukcja kończy się średnikiem ;. Nawiasy { } zbierają kilka instrukcji w jeden blok.
// zaczyna komentarz: kompilator go pomija, to notatka dla ludzi.
Wielkość liter ma znaczenie: hp i HP to dwie różne zmienne.

## Kurs 2: ruch i przyciski
Gra to pętla: 60 razy na sekundę MiniSharp woła Update (zmień stan gry) i Draw (narysuj go).
Zmienne, które mają przetrwać między klatkami, piszemy w klasie (static), a nie w metodzie.
class Game {
    static float x = 200, y = 120;        // pozycja gracza
    static int kolor = Color.Green;
    static void Update() {
        if (Input.Held(Btn.Left)) x -= 3;     // Held: przycisk trzymany
        if (Input.Held(Btn.Right)) x += 3;
        if (Input.Held(Btn.Up)) y -= 3;       // y rośnie w dół ekranu
        if (Input.Held(Btn.Down)) y += 3;
        if (x < 0) x = 0;                     // nie wychodź za ekran
        if (x > 400) x = 400;
        if (Input.Pressed(Btn.A)) kolor = Color.Red;   // Pressed: tylko w chwili wciśnięcia
    }
    static void Draw() {
        Gfx.Screen(Screen.Top);           // górny ekran: 400 x 240
        Gfx.Clear(Color.Black);           // wyczyść ekran
        Gfx.Circle(x, y, 10, kolor);      // kółko: x, y, promień, kolor
        Gfx.Text(5, 5, "x = " + (int)x, Color.White);
    }
}
Warunki łączy się przez && (i) oraz || (lub): if (x < 0 || x > 400) ...
Zamiast kilku if można napisać else: if (hp > 50) ... else if (hp > 0) ... else ...

## Kurs 3: pętle i listy
Pętla powtarza kod. Lista trzyma wiele wartości pod jedną nazwą. Razem rysują np. 50 gwiazd w tle.
static List<float> gwiazdyX = new List<float>();
static List<float> gwiazdyY = new List<float>();
static void Main() {
    for (int i = 0; i < 50; i++) {        // i = 0, 1, 2 ... 49
        gwiazdyX.Add(Random.Range(0, 400));    // Add: dopisz na koniec listy
        gwiazdyY.Add(Random.Range(0, 240));
    }
}
static void Update() {
    for (int i = 0; i < gwiazdyY.Count; i++) {     // Count: ile jest elementów
        gwiazdyY[i] += 1;                          // [i]: element numer i (liczymy od 0)
        if (gwiazdyY[i] > 240) gwiazdyY[i] = 0;    // spadła na dół: wraca na górę
    }
}
foreach (var g in lista) przechodzi po wszystkich elementach, gdy numer nie jest potrzebny.
while (warunek) { ... } powtarza, dopóki warunek jest prawdziwy.
Tablica (int[] a = new int[10]) ma stałą długość; lista rośnie, gdy dodajesz.

## Kurs 4: metody
Metoda to nazwany kawałek kodu. Dzięki metodom Update nie rośnie w jeden długi tasiemiec.
static void RysujGwiazdy() {                      // void: nic nie zwraca
    for (int i = 0; i < gwiazdyX.Count; i++) Gfx.Rect(gwiazdyX[i], gwiazdyY[i], 2, 2, Color.White);
}
static float Odleglosc(float x1, float y1, float x2, float y2) {   // parametry: dane wejściowe
    float dx = x2 - x1, dy = y2 - y1;
    return Mathf.Sqrt(dx * dx + dy * dy);         // return: wynik metody
}
static bool Trafiony(float ax, float ay, float bx, float by, float promien) {
    return Odleglosc(ax, ay, bx, by) < promien;   // metoda może wołać inne metody
}
Wywołanie: RysujGwiazdy();   if (Trafiony(x, y, wrogX, wrogY, 12)) hp--;
Krótka metoda może mieć => zamiast { return ...; }: static int Podwoj(int a) => a * 2;

## Kurs 6: dziedziczenie
Nietoperz i Kamień to różni wrogowie, ale mają wiele wspólnego (pozycję, hp, punkty).
Wspólne rzeczy idą do klasy bazowej Wrog, a każdy rodzaj wroga dopisuje tylko swoje różnice.
abstract class Wrog {                       // abstract: nie ma "zwykłego" wroga, są tylko konkretne
    public float x, y;
    public int hp, punkty;
    public Wrog(float x, int hp, int punkty) { this.x = x; y = -10; this.hp = hp; this.punkty = punkty; }
    public virtual void Ruch() { y += 1; }  // virtual: można zmienić w klasie pochodnej
    public abstract void Rysuj();           // abstract: każdy wróg MUSI mieć swoje Rysuj
}
class Nietoperz : Wrog {                    // Nietoperz jest Wrogiem
    float czas;
    public Nietoperz(float x) : base(x, 1, 10) { }   // base(...): konstruktor Wroga
    public override void Ruch() {           // override: własny ruch, zygzakiem
        base.Ruch();                        // najpierw ruch Wroga (w dół)
        czas += 0.1f;
        x += Mathf.Sin(czas) * 2;
    }
    public override void Rysuj() { Gfx.Circle(x, y, 7, Color.Magenta); }
}
class Kamien : Wrog {
    public Kamien(float x) : base(x, 3, 30) { }
    public override void Ruch() { y += 0.5f; }
    public override void Rysuj() { Gfx.Rect(x - 9, y - 9, 18, 18, Color.Gray); }
}
Najważniejsze: jedna lista na wszystkich wrogów, a każdy rusza się po swojemu.
List<Wrog> wrogowie = new List<Wrog>();
wrogowie.Add(new Nietoperz(100)); wrogowie.Add(new Kamien(300));
foreach (Wrog w in wrogowie) { w.Ruch(); w.Rysuj(); }
Nowy rodzaj wroga = nowa mała klasa; reszta gry się nie zmienia.

## Kurs 9: korutyny, czyli czekanie
Korutyna to metoda, która może się zatrzymać i wrócić później. Idealna do fal wrogów i animacji.
static IEnumerator Fale() {
    while (zycia > 0) {
        fala++;
        komunikat = "Fala " + fala;
        yield return new WaitForSeconds(1.5f);        // czekaj 1,5 s (gra działa dalej)
        komunikat = "";
        for (int i = 0; i < 3 + fala * 2; i++) {
            Dodaj(i % 3 == 2 ? new Kamien(Random.Range(20, 380)) : new Nietoperz(Random.Range(20, 380)));
            yield return new WaitForSeconds(0.6f);    // przerwa między wrogami
        }
        while (wrogowie.Count > 0) yield return null; // null: czekaj do następnej klatki
    }
}
Start w Main: StartCoroutine(Fale());
Bez korutyny trzeba by liczyć klatki w Update i pamiętać, na którym etapie jest fala.

## Loch 1: mapa z liter
Przykład loch.cs to roguelike: litery zamiast obrazków, losowy loch, walka turowa. Uruchom go z menu, potem czytaj dalej.
Mapa to tablica znaków: '#' ściana, '.' podłoga, '>' schody. Pole (x, y) ma numer y * W + x.
const int W = 40, H = 19;              // 40 x 19 pól; pole ma 10 x 12 pikseli
static char[] mapa = new char[W * H];
Generowanie: najpierw wszystko jest ścianą, potem wykuwamy pokoje i łączymy je korytarzami.
for (int proba = 0; proba < 80 && pokoje.Count < 8; proba++) {
    int w = Random.Range(4, 11), h = Random.Range(3, 6);       // losowy rozmiar
    int x = Random.Range(1, W - w - 1), y = Random.Range(1, H - h - 1);
    if (pokoje.Exists(p => x <= p[0] + p[2] && p[0] <= x + w && y <= p[1] + p[3] && p[1] <= y + h)) continue;  // nachodzi na inny
    for (int yy = y; yy < y + h; yy++) for (int xx = x; xx < x + w; xx++) mapa[yy * W + xx] = '.';
    if (pokoje.Count > 0) Korytarz(...środek poprzedniego..., ...środek nowego...);   // poziomo, potem pionowo
    pokoje.Add(new int[] { x, y, w, h });
}
Gracz staje w pierwszym pokoju, schody '>' w ostatnim, potwory i mikstury w pozostałych.
Rysowanie: każda litera osobno w swoim polu, żeby kolumny się zgadzały:
Gfx.Text(x * 10, y * 12, znaki[c], 0.45f, kolor);    // znaki[c]: gotowy napis z jedną literą
Widzisz tylko pola blisko siebie (Widac), a odkryte wcześniej ściany zostają na mapie (widziane[]).

## Loch 2: komponenty jak w Unity
W Unity GameObject sam nic nie umie; zachowanie dają mu komponenty (Rigidbody, Health...).
To samo da się zrobić w MiniSharp: wystarczy lista komponentów, dziedziczenie po jednej klasie bazowej w zupełności wystarcza.
abstract class Komponent {
    public Byt byt;                        // właściciel (jak gameObject)
    public virtual void Tura() { }         // jak Update w Unity, tylko raz na turę
}
class Byt {                                // jak GameObject
    public string nazwa; public char znak; public int x, y;
    List<Komponent> komponenty = new List<Komponent>();
    public Byt Dodaj(Komponent k) { k.byt = this; komponenty.Add(k); return this; }
    public Komponent Pobierz(Predicate<Komponent> jaki) => komponenty.Find(jaki);
    public Zdrowie PobierzZdrowie() => Pobierz(k => k is Zdrowie) as Zdrowie;   // jak GetComponent<Health>()
    public void Tura() { foreach (Komponent k in komponenty) k.Tura(); }
}
Komponenty: Zdrowie (hp i zdarzenie onSmierc), Atak (siła), AI (mózg potwora), Przedmiot (efekt jako lambda).
Potwór to zestaw klocków; nowy rodzaj potwora nie potrzebuje nowej klasy:
Byt ork = new Byt("Ork", 'O', Color.Red, 0, 0).Dodaj(new Zdrowie(15)).Dodaj(new Atak(4)).Dodaj(new AI(false));
Byt mikstura = new Byt("mikstura", '!', Color.Magenta, 0, 0).Dodaj(new Przedmiot(kto => kto.PobierzZdrowie().Lecz(12)));
Różnica z Unity: nie ma GetComponent<T>() (MiniSharp nie ma własnych generyków), dlatego Pobierz(k => k is Zdrowie) as Zdrowie.
Kiedy dziedziczenie, a kiedy komponenty? Dziedziczenie: "Boss JEST wrogiem" (Kurs 6). Komponenty: "ten byt MA zdrowie i atak", gdy cechy się mieszają.

Komponent AI trzyma bieżący stan i zmienia go:
public override void Tura() {
    Stan nowy = stan.Tura(this);
    if (nowy != null) { stan = nowy; stan.Wejdz(this); }
}
Dolny ekran pokazuje stan każdego widocznego potwora (spi / goni / ucieka).

foreach (Byt b in byty) if (b != gracz) b.Tura();                         // teraz ruszają się potwory

## Klasy
Klasa to przepis na obiekty: pola (dane) i metody (co obiekt umie).
class Gracz {
    public float x;              // pole: każdy gracz ma własne x
    public int zycia = 3;        // pole z wartością początkową
    public static int ilu = 0;   // pole static: jedno, wspólne dla całej klasy
    public Gracz(float x) {      // konstruktor; x to parametr z new
        this.x = x;              // this.x to pole obiektu, samo x to parametr
        ilu++;
    }
    public void Ruch() { x += 1; }        // tu nie ma parametru x, więc x to pole
    public bool Zyje() => zycia > 0;      // krótka metoda: => wyrażenie
    public static Gracz Nowy() { return new Gracz(0); }   // metoda static: bez obiektu
}
var a = new Gracz(10);   // parametr x = 10, więc a.x = 10
var b = new Gracz(50);   // b.x = 50, ilu = 2
a.Ruch();                // a.x = 11, b.x dalej 50
Gracz.ilu                // pole static czyta się przez nazwę klasy
Gracz c = Gracz.Nowy();  // metodę static woła się przez nazwę klasy
Gracz d = null;          // zmienna obiektu może być pusta; d.x da błąd "null reference"
Konstruktor ma nazwę klasy, nie ma typu zwracanego i uruchamia go new.
Najpierw ustawiają się wartości początkowe pól, potem działa ciało konstruktora.
Klasa bez konstruktora dostaje pusty: new Gracz().
this to obiekt, na którym działa metoda. Bez this, gdy parametr i pole mają tę samą nazwę, x = x zmieniłoby tylko parametr.
public, private, protected, internal i readonly są akceptowane, ale kompilator ich nie sprawdza (wszystko jest widoczne).
Ograniczenia: jeden konstruktor na klasę, bez przeciążania metod (dwie metody nie mogą mieć tej samej nazwy), bez właściwości get/set, bez klas zagnieżdżonych. Zobacz temat "C# a MiniSharp".

## Dziedziczenie
Klasa pochodna (Boss) dostaje wszystkie pola i metody klasy bazowej (Wrog) i może dodać swoje.
Jak w C#, klasa ma JEDNĄ klasę bazową (nie ma wielokrotnego dziedziczenia klas); kilka "ról" naraz daje się przez interfejsy.
class Wrog {
    public string imie;
    public int hp;
    public Wrog(string imie, int hp) { this.imie = imie; this.hp = hp; }
    public virtual void Trafiony(int ile) { hp -= ile; }      // virtual: klasa pochodna może to zmienić
    public void Lecz() { hp += 5; }                            // zwykła metoda: dziedziczy się bez zmian
}
class Boss : Wrog {                          // Boss jest też Wrogiem
    public int faza = 1;                     // nowe pole
    public Boss() : base("Smok", 50) { }     // base(...) woła konstruktor Wroga
    public override void Trafiony(int ile) { // override: własna wersja metody virtual
        base.Trafiony(ile / 2);              // wersja z klasy bazowej
        if (hp < 25) faza = 2;
    }
}
Wrog w = new Boss();      // zmienna typu bazowego może trzymać Bossa
w.Trafiony(10);           // wywoła się wersja Bossa (bo override), hp = 45
w.Lecz();                 // metoda z Wroga, hp = 50
w.faza                    // BŁĄD: dla kompilatora w to Wrog; użyj if (w is Boss b) b.faza ...
List<Wrog> wrogowie = new List<Wrog> { new Wrog("Szczur", 3), new Boss() };
foreach (Wrog x in wrogowie) x.Trafiony(4);   // każdy dostaje swoją wersję Trafiony
Kolejność przy new Boss(): pola Bossa, potem konstruktor Wroga, potem ciało konstruktora Bossa.
Jeśli konstruktor bazy ma parametry, klasa pochodna musi napisać : base(...).
Łańcuch może być dłuższy: class SuperBoss : Boss { ... } dostaje wszystko z Bossa i z Wroga.
Metody abstrakcyjne: klasy abstract nie da się utworzyć przez new, a klasy pochodne muszą napisać override.
abstract class Ksztalt {
    public abstract float Pole();                          // bez ciała, kończy się ;
    public string Opis() { return "pole " + Pole(); }      // może używać Pole()
}
class Kolo : Ksztalt { public float r; public override float Pole() => 3.14f * r * r; }
Każda klasa może mieć: public override string ToString() { return "Boss " + hp; }
ToString używają Console.WriteLine(obiekt) i "tekst" + obiekt. base.ToString() daje nazwę klasy.
Nie wolno: tej samej nazwy pola w bazie i w pochodnej; tej samej nazwy metody bez virtual/override; override bez virtual w bazie; ukrywania metod słowem new.

## Interfejsy, is, as
Interfejs to lista metod, które klasa obiecuje mieć (bez ciał). Klasa ma jedną bazę, ale może mieć wiele interfejsów.
interface IRaniony { void Trafiony(int ile); bool Martwy(); }
interface IPodpisany { string Nazwa(); }
interface ILeczony : IRaniony { void Lecz(int ile); }    // interfejs może rozszerzać inny
class Skrzynia : IRaniony, IPodpisany {
    int hp = 3;
    public void Trafiony(int ile) { hp -= ile; }
    public bool Martwy() => hp <= 0;
    public string Nazwa() => "skrzynia";
}
class Golem : Wrog, IPodpisany { ... }   // najpierw klasa bazowa, potem interfejsy
IRaniony r = new Skrzynia(); r.Trafiony(1);
List<IRaniony> cele = ...; foreach (var c in cele) c.Trafiony(1);  // różne klasy, ta sama metoda
Metodę interfejsu może dać klasa bazowa. Interfejs ma tylko metody (bez pól, właściwości, metod static i domyślnych ciał).
Sprawdzanie typu w czasie gry:
if (w is Boss b) b.faza = 3;     // czy to Boss? jeśli tak, b to ten sam obiekt jako Boss
if (w is IRaniony) ...           // działa też z interfejsami
Boss b2 = w as Boss;             // Boss albo null (gdy to nie Boss)
Boss b3 = (Boss)w;               // rzutowanie: błąd w czasie gry, gdy w nie jest Bossem
if (w is null) ...   if (w is not Boss) ...   if (w != null) ...
is i as działają tylko z klasami i interfejsami (nie z int, string...).

## Lambdy
Lambda to funkcja bez nazwy, którą można trzymać w zmiennej i przekazać dalej.
Func<int, int> razy2 = x => x * 2;           // bierze int, zwraca int
Func<int, int, int> suma = (a, b) => a + b;   // ostatni typ to wynik
Func<float> losowa = () => Random.Float();    // bez parametrów
Action hej = () => Console.WriteLine("hej"); // Action: nic nie zwraca
Action<string> pisz = s => { Console.WriteLine(s); };   // dłuższa: blok { }
razy2(5)   suma(2, 3)   hej()   pisz.Invoke("x")
Predicate<int> parzysta = n => n % 2 == 0;    // to samo co Func<int, bool>
Comparison<string> krotsze = (a, b) => a.Length - b.Length;
Func<int, int> f = Kwadrat;     // nazwa metody też jest funkcją
Action klik = przycisk.Klik;    // metoda konkretnego obiektu
Lambda widzi zmienne dookoła i dzieli je z metodą (domknięcie):
int licznik = 0;
Action dodaj = () => licznik++;
dodaj(); dodaj();               // licznik == 2
Lambda potrzebuje typu: var f = x => x; nie zadziała, napisz Func<int, int> f = x => x;
Bez yield w lambdzie i bez funkcji lokalnych.

## Zdarzenia, ?. i ??
Pole Action (albo event Action) to zdarzenie: można podpiąć kilka funkcji przez += i odpiąć przez -=.
class Wrog {
    public Action<Wrog> onSmierc;          // albo: public event Action<Wrog> onSmierc;
    public void Zgin() { onSmierc?.Invoke(this); }    // ?. = tylko gdy ktoś podpiął
}
wrog.onSmierc += w => punkty += 10;
wrog.onSmierc += PokazWybuch;        // metoda z parametrem Wrog
wrog.onSmierc -= PokazWybuch;
?. sięga do pola albo metody tylko, gdy obiekt nie jest null; inaczej wynik to null:
string imie = cel?.imie;              // null, gdy cel == null
cel?.Trafiony(5);                     // nic się nie dzieje, gdy cel == null
?? daje wartość zastępczą, gdy lewa strona jest null:
string n = imie ?? "nikt";
int hp = cel?.hp ?? 0;                // przy int, float... ?. musi mieć ?? (nie ma typu int?)
float m = pancerz?.Invoke(10) ?? 10;

## C# a MiniSharp
MiniSharp to podzbiór C#. Kod MiniSharp jest poprawnym C#, ale nie każdy C# działa w MiniSharp.
Jest: klasy, dziedziczenie (jedna baza), interfejsy, abstract/virtual/override, base, is/as/rzutowanie, ToString, metody =>, lambdy, Func/Action/Predicate/Comparison, zdarzenia +=/-=, ?. i ??, List, Dictionary, korutyny, string, char, tablice, switch, foreach.
Nie ma jeszcze (pisz inaczej):
- przeciążania metod i wielu konstruktorów (daj metodom różne nazwy), : this(...)
- właściwości get/set (użyj pól albo metod GetX/SetX)
- domyślnych wartości parametrów, ref, params, out (poza TryGetValue)
- inicjalizatorów obiektów new Kolo { r = 2 } (ustaw pola po new albo w konstruktorze)
- enum, struct, własnych generyków (class Pula<T>, metody <T>), klas zagnieżdżonych, partial
- object, GetType(), typeof, nadpisywania Equals/GetHashCode, przeciążania operatorów
- try/catch/throw, using (blok), interpolacji $"...", Linq
- int? (typów z ? dopuszczających null), long; double działa jak float
- ukrywania metod (new), static constructor, destruktorów, metod rozszerzających
- sprawdzania public/private/protected (są akceptowane, ale nic nie blokują); sealed nie blokuje dziedziczenia
- switch na typach (case Boss b:)
Liczby float mają pojedynczą precyzję (jak w Unity), char to znak ASCII.
